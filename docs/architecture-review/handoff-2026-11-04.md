## Vocabulary: use these terms exactly
- **module**: anything with an interface and an implementation.
- **interface**: everything a caller must know, including types, invariants, call order, error modes and memory layout.
- **depth**: a deep module puts a lot of behaviour behind a small interface. A shallow module's interface is about as complex as its implementation.
- **seam**: where one module's interface meets another's and something could be substituted. **adapter**: the concrete thing plugged into a seam.
- **leverage**: how many callers one interface serves. **locality**: whether a change or bug stays in one place.
- **Deletion test**: if you deleted the module, would complexity concentrate elsewhere (it earns its keep) or simply vanish or move (it is shallow)?
- **One adapter means a hypothetical seam; two adapters make it real.**

Don't drift into "component", "service", "API", "boundary" or "wrapper". `GLOSSARY.md` at the repo root holds the domain terms named so far. Add new terms as they settle (still to come: *visibility module*, *player view*, *game handle*, *recorder*).
