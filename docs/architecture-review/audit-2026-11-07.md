## The three claims that do not hold

### 1. ADR-0004's cache-equality proof (`1.2`)

ADR-0004 says at `:119-120` that "the cache does not change behaviour: the
32-game runs before and after it are content-identical on all 32 games", and
`:132` records the `53cf800` → `57e0883` pair as runs
`20261106T105757Z_b6be8d1087e6` → `20261106T112844Z_df41f11c7216` with
"identical on all 32 games".

No checked-in artifact compares those two runs. The two comparison files that
exist each pair **one** of them against the same baseline `7bd2f09610e6`, whose
run directory lives outside the repo (`artifacts/ismcts/op_table_ab.json:3` →
`C:\Users\mkkom\AppData\Local\Temp\kilo\a985208_runs\...`):

| File | Pair | Result |
|---|---|---|
| `op_table_ab.md:1,13` | `7bd2f09610e6` → `b6be8d1087e6` | `Content identical on all paired games: **False**` |
| `op_table_ab_after_cache.md:1,13` | `7bd2f09610e6` → `df41f11c7216` | `Content identical on all paired games: **False**` |

In `op_table_ab_after_cache.md`, 15 of 32 rows differ only in `replay_context`
and 17 differ in search results (`chosen_action_id`, `chosen_move`, `policy`,
`q_values`, `root_value`, `visit_counts`, plus downstream `final_scores`,
`winner_id`, `step_count`, `replay_log`).

Verdict: the equality claim is **Unsupported** (no artifact for that pair), and
the "`replay_context` is the only field that differs" explanation at `:134-137`
is **Contradicted** by both files.

This is not proof the cache changed behaviour. Both candidate runs come from a
tree at `engine_git_sha 53cf800`, `engine_git_dirty: true`, so their identity
is the DLL hash (`cc7e66…` for `b6be8d`, `59a163…` for `df41f11`). The honest
statement is: *the ADR's evidence does not show the cache is behaviour-neutral,
and the artifacts that do exist show 32-game runs differing in search.*

### 2. ADR-0004's "colon parser remains only for `custom_effect`" (`1.2`)

`:90-92` says the colon parser and `find_sel`/`atoi` code "now remain only for
the deferred `custom_effect` dispatcher".

`engine_c/generic_runtime.c:1029-1275` is one `strcmp` chain. Branches
`:1030-1153` cover the 12 migrated ops and are unreachable:

```
1030  deploy_troops / place_spy
1035  assassinate_troop / supplant_troop
1054  return_spy
1056  promote_card
1073  recruit_card
1075  devour / devour_cost
1077  force_discard
1086  return_unit
1100  move_troop
1131  play_card
```

`:1154-1269` is the `custom_effect` branch and is still live. `:1270-1275` are
the fall-throughs for an unmatched or NULL op, which only the migrated ops can
reach. So the dead surface is `:1030-1153` plus `:1270-1275` — 130 lines — while
116 lines must stay.

The op path at `:800-1021` returns before reaching any of it, so the migrated
ops never fall through. Deleting `:1030-1153` and folding `:1270-1275` into the
`custom_effect` `else` would make the ADR true and leave exactly one
implementation of each op's payload decoding.

### 3. `make clean` drift (`0.2`)

`tests.txt:8` lists `test_visibility`. It is missing from `clean`. The manifest

## Top recommendation

**Delete the dead half of `engine_c/generic_runtime.c:1029-1275`** (specifically
`:1030-1153` and `:1270-1275`, keeping the live `custom_effect` branch).

It is the only change that moves a module from 3/5 to 4/5 on the deletion test
without touching behaviour, and it makes ADR-0004:90-92 true instead of false.
The 13 migrated ops all reach `card_op_for` at `:800` first, so the branches are
unreachable; removing them shrinks the file by ~130 lines and leaves exactly one
implementation of each op's payload decoding. Then fix the ADR's cache claim and
the `Makefile` clean list, in that order, because both are small and both are
currently telling a reader something untrue.

The visibility module should not be touched until step 2 is scoped: it is the
deepest of the four and its remaining work is a rules decision, not a
refactor.
