# Game Viewer Rendering Plan

## Scope
Update the Tk game viewer map so it matches the board creator's board styling more closely, adds route/site ownership cues, and starts zoomed out enough to show the whole board.

## Assumptions
- Reuse the existing shared `GameBoardRenderer` where possible, because both `game_viewer` and `replay_viewer` already depend on it.
- Keep changes surgical: prefer a small shared geometry/styling layer or a narrow renderer refactor over introducing a new rendering subsystem.
- "Pan out to show the whole board" requires actual zoom-to-fit support, not just scrolling, because the current viewer only shows a fixed-size viewport over a full-size layout canvas.
- Site VP text should show printed `vp_value`, not a dynamic scoring projection.

## Key Findings
- `interface/game_renderer.py` currently draws both geometry and occupancy overlays for `game_viewer` and `replay_viewer`.
- `interface/board_renderer.py` already has the site/route shape treatment you want in the board creator: site labels above site bounds and routes as a single labeled circle.
- `game_viewer.py` does not currently have zoom transforms; it only renders a fixed-size canvas with scrollbars.
- `control_marker` means unique troop-majority control, not total control.
- Total control exists in `engine.scoring._is_total_control`, but it is not currently exposed in `GameView`.

## Recommended Chunking

### 1. Define the renderer-facing board state
Goal: expose exactly the gameplay facts the renderer needs, and nothing extra.

Work:
- Keep site VP text sourced from existing printed `vp_value`.
- Add a small projection/helper path for renderer-facing board display data only if `GameBoardRenderer` cannot derive everything cleanly from current `GameView`.
- Expose whether a site has total control, because `control_marker` alone is not enough for the requested border color.
- Keep route ownership derived from the existing single troop slot when possible.

Verify:
- Add or update pure tests around any new helper/view fields.
- Confirm route owner, site owner, printed VP, and total-control status are derivable without Tk.

### 2. Unify node geometry/styling with board creator visuals
Goal: make site and route shapes in the game viewer look like the board creator, without changing unrelated UI.

Work:
- Compare `interface/board_renderer.py` and `interface/game_renderer.py` and port the site/route drawing conventions into the gameplay renderer.
- Sites:
  - draw using the site bounds like board creator
  - move the site name above the site box
- Routes:
  - draw as a single circle
  - render the route number centered inside
  - stop using the current route troop-slot-style dot overlay
- Keep edge drawing behavior consistent with current topology rendering unless the styling mismatch is directly caused by route/site redraw logic.

Verify:
- Expand `tests/test_game_renderer.py` canvas-stub assertions to check expected rectangle/oval/text calls for both site and route nodes.

### 3. Add gameplay overlays for ownership and scoring cues
Goal: replace noisy occupancy text with the specific information requested.

Work:
- Sites:
  - inside the site, render text only for owner and printed VP value
  - color the site border with player color when the site has total control
  - otherwise keep neutral border/highlight behavior
- Routes:
  - fill empty routes gray
  - fill routes white when occupied by a white troop
  - fill routes with player color when occupied by a player troop
- Preserve selection/highlight behavior so clicking nodes still communicates focus.
- Decide whether spy badges remain visible; if retained, place them so they do not fight with the new site-name-above / owner+VP-inside layout.

Verify:
- Add renderer tests for:
  - empty route fill
  - white route fill
  - player-owned route fill
  - total-control site border color
  - site text content format

### 4. Add lightweight camera support to the game viewer
Goal: allow the map to open zoomed out to the full board instead of a cropped scroll view.

Work:
- Introduce a minimal viewer camera model (`zoom_level` plus world/screen transforms) instead of copying the full editor interaction stack.
- Reuse the board creator's fit-to-content math as the reference for initial zoom-to-fit behavior.
- Update renderer usage and click hit-testing so node selection still works under zoom.
- Preserve the existing scrollbars, but make them operate on the scaled canvas.

Verify:
- Extract any fit/transform math into a small pure helper if needed, then unit test the computed fit zoom / centering.
- Manually verify initial load opens with the whole board visible and node clicking still selects the right node.

### 5. Wire startup behavior and shared-renderer blast radius
Goal: finish integration cleanly and avoid regressions in the replay viewer.

Work:
- Trigger zoom-to-fit after the viewer has built the map canvas and after switching maps.
- Let `replay_viewer` inherit the shared board styling from `GameBoardRenderer`, but keep camera behavior local to `game_viewer.py` unless replay also needs fit-to-board.
- Update any default-path tests or setup tests that still point at incomplete base layout fixtures if they become part of the exercised path.

Verify:
- Smoke-check `game_viewer` startup on the default map.
- Smoke-check `replay_viewer` rendering after shared renderer changes.
- Run targeted renderer/viewer tests first, then the broader pytest slice covering viewer setup and renderer behavior.

## Suggested Execution Order
1. Add or extend pure view/helper coverage for total-control and route-owner facts.
2. Add renderer tests that describe the desired site/route output.
3. Update `GameBoardRenderer` to match board creator visuals and new ownership overlays.
4. Add lightweight zoom-to-fit support to `game_viewer.py`.
5. Smoke-check `replay_viewer` because it shares the renderer.

## Main Risk Areas
- `GameBoardRenderer` is shared by `game_viewer` and `replay_viewer`, so visual changes will affect both.
- Total control is not currently exposed in `GameView`, so trying to infer it from `control_marker` would be wrong.
- Zoom support changes click-hit-testing; if transforms are added only in drawing and not in selection, node clicks will break.
- The current `tests/test_game_renderer.py` coverage is shallow, so renderer regressions are likely unless tests are expanded first.

## Minimal Success Criteria
- Sites render with board-creator-style geometry and site names above the box.
- Routes render as a single numbered circle with occupancy-based fill color.
- Site interior text is reduced to owner + printed VP value.
- Sites with total control use player-colored borders.
- Game viewer opens with the full board visible on startup.
- Shared renderer changes are either validated for replay viewer or explicitly isolated from it.
