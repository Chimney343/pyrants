# Insane Outcast Implementation Plan

## Goal
Implement Insane Outcast so that playing it always resolves as:
1. play `insane_outcast`
2. choose another card from the same player's hand and discard that card to that player's discard pile
3. remove the played `insane_outcast` from `played_cards`, which returns it to the regular Insane Outcast recruit deck in the same way House Guard and Priestess of Lolth use their existing recruit decks

## Key Implementation Assumption
The engine already models House Guard, Priestess of Lolth, and Insane Outcast through the same existing special-recruit deck path in `SPECIAL_RECRUIT_STACKS` and `_apply_recruit(...)`. There is no separate explicit supply zone for any of them. Availability is derived by `_remaining_special_stack_count(...)` from copies currently owned in player zones. Because of that, "return to the Insane Outcast deck" should be implemented by removing the played copy from player-owned zones rather than adding a new state container.

## Scope Decision
Implement the requested play-time behavior exactly and make the execution model express that behavior explicitly. Do not keep the current no-op `self_purge_to_supply` behavior. If the old devour/promote text is still present in source data, update the source-of-truth text so future catalog regeneration does not reintroduce a mismatch.

## Planned Engine Changes
### 1. Add a narrow play precondition for Insane Outcast-style effects
Introduce a helper used by both `legal_moves(...)` and `_apply_play_card(...)` so cards that require discarding another hand card cannot be played from a one-card hand.

Why this is needed:
- the generic interpreter currently skips required-selection actions when no legal target exists
- if Insane Outcast were modeled as a sequence without prevalidation, it could incorrectly skip the discard step and still advance
- the requested behavior is mandatory, not optional

Expected rule:
- `PlayCardMove(..., card_id="insane_outcast")` is legal only when the player will still have at least one card in hand after removing the played Insane Outcast
- direct `apply(...)` should raise `IllegalMoveError` if this precondition is not met

### 2. Replace the Insane Outcast no-op custom effect with explicit sequence steps
Update the Insane Outcast execution model so it is no longer a single `self_purge_to_supply` action.

Preferred shape:
- action 1: `custom_effect` that requires selecting one hand card belonging to the current player and discards it to that player's discard pile
- action 2: `custom_effect` that removes `source_card_id` from the current player's `played_cards`

This keeps the execution model aligned with the exact requested order.

### 3. Extend generic selection support for the new discard step
In `engine/rules.py`:
- update `_action_requires_selection(...)` so the new discard-self-hand custom effect requires selection
- extend `_legal_generic_target_selection_moves(...)` so the new effect yields one `ResolveGenericChoiceMove` per eligible hand index in the active player's hand
- selection payload should use `hand_index` and should only target the active player's remaining hand after Insane Outcast has already been played

### 4. Implement the two custom effect handlers
In `_apply_generic_custom_effect(...)` add handlers for the new effect kinds.

Handler A: discard selected self hand card
- validate `hand_index`
- pop that card from `updated.players[player_id].hand`
- append it to `updated.players[player_id].discard_pile`

Handler B: return played source card to the regular Insane Outcast recruit deck
- locate `source_card_id` in `updated.players[player_id].played_cards`
- remove that one played copy
- do not move it into discard, devour, inner circle, or any other zone

Implementation note:
- this second handler should use `source_card_id` instead of hard-coding `insane_outcast`, so the primitive remains generic and the card data decides where it is used
- returning to the deck should reuse the same implicit deck-availability model already used by House Guard and Priestess of Lolth rather than inventing a different Insane Outcast-only path

### 5. Keep recruit-deck accounting implicit
No new state fields should be added for Insane Outcast deck tracking.

Reason:
- `_remaining_special_stack_count(...)` already computes remaining deck size from total copies minus copies currently owned in player zones
- `SPECIAL_RECRUIT_STACKS` already treats Insane Outcast the same way as House Guard and Priestess of Lolth, just with a different slot id, total count, and expansion gate
- removing the played copy from `played_cards` is enough to make it available again in the regular Insane Outcast recruit deck

### 11. Replace the old no-op generic test
In `tests/test_generic_interpreter.py`:

### 12. Add real-card behavior tests in `tests/test_rules.py`
Replace the current Insane Outcast smoke test with behavior tests against the real catalog card.

Test A: happy path
- start with hand like `['insane_outcast', 'noble', 'soldier']`
- play Insane Outcast
- assert a pending generic choice exists for selecting another hand card
- resolve the choice for one specific hand index
- assert:
  - chosen card moved to the current player's discard pile
  - `insane_outcast` is not in `played_cards`
  - `insane_outcast` is not in hand or discard
  - any unchosen hand card remains in hand
  - optional: remaining Insane Outcast recruit-deck count increased by one compared with the post-play/pre-resolution intermediate state

Test B: cannot play without another hand card
- start with hand `['insane_outcast']`
- assert `legal_moves(state)` does not offer `PlayCardMove(..., card_id='insane_outcast')`
- assert a direct `apply(state, PlayCardMove(...))` raises `IllegalMoveError`

If useful, add a test that reads the real `insane_outcast` definition from `data/cards/catalog.json` and asserts its execution model is the intended two-step sequence in the intended order.

## Minimal-Change Preference
Prefer adding the smallest reusable primitives needed for this card:
- one playability precondition helper
- one custom effect for discarding a selected self-hand card
- one custom effect for returning the played source card to the existing recruit-deck path implicitly

Avoid introducing a new permanent supply zone or broader generic-action abstractions unless the existing custom-effect path proves insufficient.
